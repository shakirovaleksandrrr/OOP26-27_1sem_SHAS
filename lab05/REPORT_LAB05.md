1. Концепция Java Collections Framework и обобщений (Generics)
1.1. Назначение и иерархия интерфейсов: Collection, List, Set, Map
Java Collections Framework (JCF) — это унифицированная архитектура для представления коллекций данных и манипулирования ими. Иерархия разделена на две независимые ветви:
1. `java.util.Collection` — корневой интерфейс для последовательностей элементов:
   - `List` (список) — упорядоченная последовательность с доступом по целочисленному индексу; допускает дубликаты (`ArrayList`, `LinkedList`).
   - `Set` (множество) — коллекция без повторяющихся элементов; опирается на контракт `equals()` и `hashCode()` (`HashSet`) либо на `Comparable`/`Comparator` (`TreeSet`).
   - `Queue` / `Deque` (очередь / двусторонняя очередь) — коллекции для организации очередей обработки данных (FIFO, LIFO).
2. `java.util.Map` (ассоциативный массив / словарь) — хранилище пар «ключ — значение» с уникальными ключами (`HashMap`, `LinkedHashMap`, `TreeMap`). Не наследует интерфейс `Collection`, но интегрирован в каркас через методы `keySet()`, `values()`, `entrySet()`.

Контрольный вопрос: В чем различие между Collection и Map?
`Collection` хранит отдельные изолированные элементы ($E$). `Map` хранит отображение между уникальными ключами и значениями ($K \to V$). Ключи не могут дублироваться, а значения могут повторяться.

1.3. Ответы на вопросы к Заданию
Почему нельзя написать new T() для обобщенного типа в Java?
Вследствие механизма стирания типов (Type Erasure) информация о конкретном типе $T$ удаляется компилятором на этапе компиляции, и во время выполнения (runtime) виртуальная машина JVM не знает точного конструктора класса $T$.

Почему следует категорически избегать использования raw types (например, List list)?
При использовании raw types отключается контроль типов компилятора (compile-time type safety). Программист может случайно поместить в список объект любого типа, что приведет к трудноотслеживаемому выбросу `ClassCastException` во время выполнения.

3. Сравнительный анализ и экспериментальные исследования
3.1. Эксперимент 1: ArrayList vs LinkedList (50 000 элементов)
Результаты замеров на 4 сценариях:
1. **Добавление в конец**: `ArrayList` (2 мс) быстрее `LinkedList` (6 мс). Причина: `ArrayList` последовательно заполняет непрерывный массив в памяти, а `LinkedList` на каждый элемент выделяет новый объект `Node` в куче, создавая нагрузку на Garbage Collector.
2. **Последовательный проход**: `ArrayList` (1 мс) быстрее `LinkedList` (3 мс). Причина: Процессорный кэш (L1/L2 Cache) отлично предзагружает последовательные ячейки памяти массива (`Cache Locality`). Для связного списка узлы разбросаны по всей куче, что вызывает постоянные кэш-промахи (`cache misses`).
3. **get(i) по случайным индексам**: `ArrayList` (1 мс) колоссально быстрее `LinkedList` (1410 мс!). Причина: У `ArrayList` доступ по индексу выполняется мгновенно за $O(1)$ по формуле смещения `base_address + index * 4`. У `LinkedList` доступ требует последовательного прохода от начала или конца списка за $O(N)$.
4. **Вставка в середину через ListIterator**: `LinkedList` (1 мс) быстрее `ArrayList` (4 мс). Причина: У `LinkedList` вставка при готовом итераторе требует лишь переброски ссылок `prev` и `next` за $O(1)$. У `ArrayList` требуется сдвиг половины элементов массива вправо через `System.arraycopy` ($O(N)$).

3.2. Эксперимент 2: Эффективность поиска на 100 000 транзакциях (List vs Map)
- Поиск 100 случайных транзакций в `List<Transaction>` (линейный перебор $O(N)$): **126 мс**.
- Поиск тех же 100 транзакций в `Map<UUID, Transaction>` (хеш-индекс $O(1)$): **118 микросекунд** (0.118 мс).
- **Вывод**: Хеш-таблица обеспечивает ускорение более чем в **1000 раз**, доказывая критическую важность правильного выбора структуры данных при масштабировании нагрузки.

3.3. Эксперимент 3: Стирание типов (Type Erasure) в JVM
```java
List<String> strings = new ArrayList<>();
List<Integer> integers = new ArrayList<>();
System.out.println(strings.getClass() == integers.getClass()); // Выводит true!
```
Виртуальная машина JVM во время выполнения не различает типы `List<String>` и `List<Integer>`. Информация о параметрах типов стирается до границы `java.util.ArrayList`.

4. Обобщенное программирование (Generics) и контракт репозитория
4.1. Обобщенный интерфейс Repository<T, ID> и контракт Identifiable<ID>
```java
public interface Identifiable<ID> {
    ID getId();
}

public interface Repository<T, ID> {
    void save(T entity);
    void saveAll(Iterable<? extends T> entities);
    Optional<T> findById(ID id);
    List<T> findAll();
    boolean deleteById(ID id);
    long count();
}
```

4.2. Использование Optional<T>
Вместо возврата «магического» значения `null`, чреватого непреднамеренными `NullPointerException`, метод `findById` возвращает `Optional<T>`. Это делает отсутствие значения явным в сигнатуре метода и обязывает клиентский код обработать оба исхода (`isPresent()`, `orElse()`, `map()`).

4.3. Принцип PECS (Producer Extends, Consumer Super)
- **Producer Extends**: Если коллекция является источником данных для чтения («производит» элементы $T$), используется wildcard `<? extends T>`. Это позволяет безопасно читать элементы как тип $T$. Пример: `saveAll(Iterable<? extends T> entities)`.
- **Consumer Super**: Если коллекция выступает приемником для записи («потребляет» элементы $T$), используется wildcard `<? super T>`. Это позволяет гарантировать, что любой объект подтипа $T$ может быть добавлен в целевой список. Пример: `copy(List<? extends T> src, List<? super T> dest)`.

5. Сортировка: Comparable и Comparator
- **Естественный порядок (`Comparable<Transaction>`)**: Реализован в классе `Transaction` (хронологический по возрастанию дат, при совпадении дат — по UUID).
- **Альтернативные порядки (`Comparator<Transaction>`)**:
  1. По дате: `Comparator.comparing(Transaction::getDate)`.
  2. По сумме убывание: `(t1, t2) -> t2.getAmount().compareTo(t1.getAmount())`.
  3. Многоуровневый: по названию категории, затем по дате: `Comparator.comparing((Transaction t) -> t.getCategory().getName()).thenComparing(Transaction::getDate)`.

6. Программная реализация репозитория и сервисов
6.1. InMemoryRepository.java
```java
package edu.course.lab05.repository;

import edu.course.lab05.model.Identifiable;
import java.util.*;

public class InMemoryRepository<T extends Identifiable<ID>, ID> implements Repository<T, ID> {

    private final Map<ID, T> storage = new LinkedHashMap<>();

    @Override
    public void save(T entity) {
        if (entity == null || entity.getId() == null) {
            throw new IllegalArgumentException("Сущность или ID не могут быть null");
        }
        storage.put(entity.getId(), entity);
    }

    @Override
    public void saveAll(Iterable<? extends T> entities) {
        if (entities == null) return;
        for (T entity : entities) save(entity);
    }

    @Override
    public Optional<T> findById(ID id) {
        if (id == null) return Optional.empty();
        return Optional.ofNullable(storage.get(id));
    }

    @Override
    public List<T> findAll() {
        return new ArrayList<>(storage.values());
    }

    @Override
    public boolean deleteById(ID id) {
        if (id == null) return false;
        return storage.remove(id) != null;
    }

    @Override
    public long count() {
        return storage.size();
    }
}
```

Ключевые механизмы байт-кода:
`checkcast` — инструкция приведения типа, которую компилятор автоматически генерирует в точках извлечения объектов из обобщенных коллекций.

8. Ответы на контрольные вопросы к защите
Чем отличаются List, Set, Map и когда применять каждую структуру?
`List` хранит упорядоченную последовательность элементов с доступом по индексу и дубликатами. `Set` хранит уникальные элементы без дубликатов (для контроля уникальности). `Map` хранит пары «ключ-значение» (для быстрого поиска значения по уникальному ключу).

ArrayList vs LinkedList: отличия по сложности операций и сценарии выбора?
`ArrayList` базируется на динамическом массиве: чтение по индексу $O(1)$, вставка в конец $O(1)$ амортизированное, вставка в середину $O(N)$. Благодаря локальности кэша процессора почти всегда превосходит `LinkedList`. `LinkedList` — двусвязный список: доступ по индексу $O(N)$, вставка/удаление по итератору $O(1)$.

HashMap vs TreeMap, HashSet vs TreeSet: чем отличаются и что дают сортируемые структуры?
`HashMap` и `HashSet` основаны на хеш-таблицах, не гарантируют порядок элементов, но обеспечивают константную скорость $O(1)$. `TreeMap` и `TreeSet` основаны на красно-черных деревьях, обеспечивают логарифмическую сложность $O(\log N)$, но гарантируют отсортированный порядок элементов.

Зачем нужны интерфейсы Comparable и Comparator?
`Comparable` реализуется самим классом для задания естественного порядка сортировки по умолчанию (`compareTo()`). `Comparator` объявляется как отдельный внешний объект для задания гибких альтернативных правил сортировки (по сумме, дате, категории).

Для чего нужны generics и какие у них ограничения (Type Erasure)?
Обобщения (Generics) обеспечивают строгую проверку типов на этапе компиляции без ручных кастов. Ограничения: параметры типов стираются во время компиляции, поэтому в рантайме нельзя создать `new T()`, создать массив обобщенного типа `new T[10]` или использовать примитивные типы (`List<int>` запрещен, только обертки `List<Integer>`).

В чем суть правила PECS?
«Producer Extends, Consumer Super». Если коллекция производит данные для чтения, используется `<? extends T>`. Если коллекция потребляет данные для записи, используется `<? super T>`.
